# Mythfits | Codex onboarding

Prepared November 25, 2026. This is a handoff package, not a replacement website.

## Start here
1. Extract this ZIP **outside** your existing repository first.
2. Open your existing Mythfits repository in Codex Desktop. Check that your current work is saved and inspect `git status`.
3. Copy the extracted `mythfits-codex-onboarding` directory into the repository as a temporary staging directory, without overwriting anything. Alternatively, give Codex read access to the extracted directory if your workspace permissions allow it.
4. Start a task in that repository and paste the contents of `START_HERE.md`. Let Codex review existing instructions and propose how to merge this context before it edits the site.
5. Develop on `feature/phoenix-awakening` (or an equivalent new branch) and review the local preview before merging or deploying.

## What's included
- `AGENTS.md`: proposed repository-level operating instructions. Merge with any existing instructions, rather than replacing them.
- `docs/VISION.md`: mission, present-day offering, future lab and operating philosophy.
- `docs/BRAND.md`: visual identity, language and creative principles.
- `docs/DESIGN.md`: approved creative direction, animation reference, content requirements and acceptance criteria.
- `docs/ROADMAP.md`: staged development priorities.
- `prototypes/mythfits-awakening-v3.html`: self-contained interactive reference, copied unchanged from the latest prototype.
- `assets/phoenix/`: original generated transparent artwork and the optimized image embedded in the prototype.
- `START_HERE.md`: first assignment for Codex.

## Source of truth
The founder's explicit decisions and existing repository instructions take precedence. The live site at https://mythfits.io/ and existing source are the baseline for functionality and copy; the v3 HTML is the visual/interaction reference, not a complete production replacement. Proposed tokens, engineering rules and future phases are defaults to review, not previously approved mandates.

No repository was accessed or modified in preparing this package. The actual stack, deployment workflow, existing working tree, contact-form integration, licensing/asset provenance requirements and exact production design tokens must be verified in the repository. The prototype was previously reported as browser-tested in chat; this packaging pass verifies file integrity, not a new browser test.
